## 1. The 6 source files and how they connect

### 1.1 `#include` map (which file pulls in which)

```
main.cpp ----> oop.h ----> library.h
oop.cpp  ----> oop.h ----> library.h
list.c   ------------------> library.h
search.c ------------------> library.h
```
- `library.h` is the **common ground**: every file includes it (directly or through `oop.h`).
- `oop.h` is C++ only (it has classes). C files never include it.

### 1.2 Compile and link pipeline

```
list.c   --gcc-->  list.o   \
search.c --gcc-->  search.o  \___ g++ (link) ___>  library   (the program)
oop.cpp  --g++-->  oop.o     /
main.cpp --g++-->  main.o   /
```
| Step | Why |
|---|---|
| `.c` files compiled by **gcc** | They are C code (no classes). |
| `.cpp` files compiled by **g++** | They use classes, `string`, `cout`. |
| Final link by **g++** | The linker joins the 4 pieces; g++ also adds the C++ library. |
| `extern "C"` in `library.h` | Without it, g++ looks for C++-style names and the link fails ("undefined reference"). |

### 1.4 Dependency rules (important for team work)

| Rule | Meaning |
|---|---|
| **C never calls C++** | `list.c` and `search.c` do not know `oop.cpp` exists. Safe to test them alone. |
| **C++ calls C only through `library.h`** | `oop.cpp` uses the functions listed in the header, nothing else. |
| **`list.c` and `search.c` call each other** | `list.c` needs `findById`/`buildIndexes` (hash and BST live in search.c). `search.c` needs `getHead`, `printBookHeader`, `displayBook` (list and printing live in list.c). This two-way link is fine in C because `library.h` declares both sides. |
| **`main.cpp` is the only entry** | The `main()` function is only in `main.cpp`. |

**One-line layering:**
`main.cpp` -> `oop.cpp` (users, menus, recommendation) -> `list.c` + `search.c` (data engine) -> `data/*.txt`.

## 2. Who owns the data (memory and files)

### 2.1 Single source of truth
Book data lives in **one place only: the linked list in `list.c`** (`head`).
`search.c` stores only **pointers** to those same nodes, so nothing is duplicated and an issue/return is instantly visible everywhere.

```
                  linked list (list.c)
  head -> [Book 301] -> [Book 105] -> [Book 201] -> ...
              ^             ^             ^
              |             |             |   (pointers only)
   hash table (search.c)  slot 4 -> 105 ... slot 100 -> 201 ...
   BST (search.c)         tree of titles, each node points to a Book
```

### 2.2 Who creates and who frees memory
| Memory | Created by | Freed by | Lifetime |
|---|---|---|---|
| `Book` nodes | `loadBooks`, `addBook` (`malloc`) | `deleteBook`, `freeList` (`free`) | Whole program (until deleted) |
| Hash nodes (`HNode`) | `buildIndexes` -> `hashInsert` | `hashClear` (at next rebuild) | Until next add/delete/load |
| Tree nodes (`TNode`) | `buildIndexes` -> `bstInsert` | `bstClear` (at next rebuild) | Until next add/delete/load |
| Sort array `arr[MAX_BOOKS]`, recommender arrays `cand[]`, `score[]`, `history[]` | local fixed arrays (automatic) | freed automatically when the function ends | One call - no `new/delete` needed |
| `Student` / `Admin` object | `loginUser` (`new`) | `main` (`delete u`) | One login session |

Only `list.c` creates or deletes `Book` nodes. Because `buildIndexes` runs after every add/delete, the hash table and BST never hold a pointer to a freed book.

### 2.3 Who reads and writes which file
| File | Read by | Written by |
|---|---|---|
| `data/books.txt` | `loadBooks` (at start) | `saveBooks` (after add, delete, issue, return) |
| `data/issues.txt` | `readRecords` (history, return, admin report) | `issueBook` (append), `returnBook` (rewrite via `writeRecords`) |
| `data/users.txt` | `loginUser`, `userExists` | `Admin::addStudentAccount` (append) |

## 4. Code-wise explanation (key code, line by line)

### 4.1 The `Book` structure (`library.h`)
```c
typedef struct Book {
    int  id;                    // unique number
    char title[TITLE_LEN];      // 60 chars max
    char author[AUTHOR_LEN];    // 40
    char genre[GENRE_LEN];      // 30
    int  available;             // 1 on shelf, 0 issued
    int  timesIssued;           // popularity counter
    struct Book *next;          // address of the next book (the "link")
} Book;
```
- `typedef struct Book {...} Book;` - lets us write `Book` instead of `struct Book`.
- `next` is what turns separate books into a **list**: book 1 knows where book 2 is, and so on; the last one has `next = NULL`.

### 4.2 Reading one line of `books.txt` (`splitLine` + `loadBooks`, `list.c`)
```c
int splitLine(char *line, char *parts[], int max) {
    int n = 0;
    char *p;
    line[strcspn(line, "\r\n")] = '\0';      // cut the newline at the end of the line
    p = strtok(line, "|");                    // first piece (text before the first |)
    while (p != NULL && n < max) {
        parts[n] = p;  n++;
        p = strtok(NULL, "|");                // next piece
    }
    return n;                                 // how many pieces were found
}
```
```c
if (splitLine(line, parts, 6) != 6) continue;      // not exactly 6 pieces -> skip the line
b = (Book *)malloc(sizeof(Book));                  // ask memory for ONE node
b->id = atoi(parts[0]);                            // atoi: text "201" -> number 201
cleanText(b->title,  parts[1], TITLE_LEN);         // copy text safely
...
appendNode(b);                                     // add to the list
```
- `strtok(line, "|")` cuts the text at each `|`. Example: `"201|The Hobbit|Tolkien"` -> `"201"`, `"The Hobbit"`, `"Tolkien"`. It returns `NULL` when no pieces are left.
- `strcspn(line, "\r\n")` finds where the newline starts, so we can cut it off. This also removes the `\r` of Windows files.
- `parts[]` is an array of text pointers that point **inside** `line` (no copy yet); `cleanText` copies each piece into the book node.
- `!= 6` means a half-broken line is skipped instead of crashing. `splitLine` is also used for `issues.txt` (3 pieces) and `users.txt` (3 pieces).

### 4.3 Adding at the end (`appendNode`)
```c
node->next = NULL;                    // new last node points to nothing
if (head == NULL) { head = node; return; }   // empty list: it becomes the first
cur = head;
while (cur->next != NULL) cur = cur->next;   // walk to the last node
cur->next = node;                            // old last node now links to it
```
```
before: head -> [A] -> [B] -> NULL
after : head -> [A] -> [B] -> [NEW] -> NULL
```

### 4.4 Deleting a node (`deleteBook`)
```c
Book *cur = head, *prev = NULL;
while (cur != NULL && cur->id != id) { prev = cur; cur = cur->next; }  // find it, remember the one before
if (cur == NULL) return 0;              // not found
if (cur->available == 0) return -1;     // issued: refuse
if (prev == NULL) head = cur->next;     // deleting the first node: head moves forward
else prev->next = cur->next;            // skip over cur
free(cur);                              // release its memory
saveBooks(); buildIndexes();            // update file and hash/BST (they pointed to cur!)
```
```
before: [A] -> [B] -> [C]        delete B
after : [A] ---------> [C]       ([B] freed)
```
`buildIndexes()` is essential: without it the hash table/BST would still point to freed memory.

### 4.5 Hashing (`search.c`)
```c
static int hashId(int id) { return id % HASH_SIZE; }      // HASH_SIZE = 101 -> slot 0..100

static void hashInsert(Book *b) {
    int h = hashId(b->id);
    HNode *n = malloc(sizeof(HNode));
    n->book = b;                 // store the POINTER, not a copy
    n->next = table[h];          // new node points to the old first node of this slot
    table[h] = n;                // new node becomes the first (insert at front)
}

Book *findById(int id) {
    HNode *cur = table[hashId(id)];          // jump straight to the slot
    while (cur != NULL) {                    // walk only this slot's small chain
        if (cur->book->id == id) return cur->book;
        cur = cur->next;
    }
    return NULL;                             // not found
}
```
Slot 0 example: ids 101, 202, 303, 404 all have remainder 0, so slot 0 holds a chain of 4; the `if` picks the right one.

### 4.6 BST insert, exact search, and A-Z walk (`search.c`)
```c
static TNode *bstInsert(TNode *node, Book *b) {
    if (node == NULL) { /* make a new node holding b */ return node; }      // empty spot found
    if (compareText(b->title, node->book->title) < 0)
        node->left  = bstInsert(node->left, b);      // smaller title -> go left
    else
        node->right = bstInsert(node->right, b);     // otherwise -> go right
    return node;
}
```
*Recursive*: the function calls itself on the smaller problem (left or right subtree) until it hits an empty place.

```c
Book *findByTitle(const char *title) {
    TNode *cur = root;
    while (cur != NULL) {
        int c = compareText(title, cur->book->title);
        if (c == 0) return cur->book;            // exact match
        cur = (c < 0) ? cur->left : cur->right;  // smaller -> left, bigger -> right
    }
    return NULL;
}
```
```c
static void walkContains(TNode *node, const char *word, int *count) {
    if (node == NULL) return;
    walkContains(node->left, word, count);           // 1. everything smaller first
    if (containsText(node->book->title, word)) {     // 2. this node
        if (*count == 0) printBookHeader();          //    print header once, before first hit
        displayBook(node->book); (*count)++;
    }
    walkContains(node->right, word, count);          // 3. everything bigger last
}
```
Left -> node -> right on a BST = **sorted A-Z**. `count` is passed as a pointer so all recursive calls update the same counter.

### 4.7 Sorting (`showSorted`, `search.c`)
```c
Book *arr[MAX_BOOKS];                     // fixed array of pointers (no malloc needed)
...
for (i = 0; i < n - 1; i++) {             // each round puts one more item in its final place
    for (j = 0; j < n - 1 - i; j++) {     // compare neighbours
        if (isAfter(arr[j], arr[j + 1], mode)) {   // wrong order?
            temp = arr[j];                // swap them using a helper variable
            arr[j] = arr[j + 1];
            arr[j + 1] = temp;
        }
    }
}
```
- **Bubble sort**: neighbours are compared and swapped if needed; after round 1 the "biggest" item is at the end, after round 2 the second biggest, and so on.
- `arr` holds **pointers** to books, so sorting never touches the linked list.
- `isAfter(a, b, mode)` is the only part that changes between "by title", "by author" and "by popularity".

### 4.8 Issue and return (`list.c`)
```c
int issueBook(const char *user, int id) {
    Book *b = findById(id);              // hash lookup
    if (b == NULL) return 0;             // no such book
    if (b->available == 0) return -1;    // someone has it
    b->available = 0;                    // mark issued (in memory)
    b->timesIssued++;                    // popularity +1
    /* append "user|id|ISSUED" to issues.txt */
    saveBooks();                         // write books.txt
    return 1;
}
```
`returnBook` loads all history lines, looks for **this user + this id + status ISSUED**, changes it to `RETURNED`, rewrites `issues.txt`, sets `available = 1`, saves. A user cannot return a book somebody else issued, because the user name must match.

### 4.9 Classes and virtual functions (`oop.h`)
```cpp
class User {
protected:
    std::string username;                 // children can use it, outsiders cannot
public:
    virtual ~User() {}                    // so deleting via User* cleans the child too
    virtual std::string getRole() = 0;    // "= 0": children MUST provide this
    virtual void menu() = 0;
    void searchByTitle();                 // normal (shared) functions
};
class Student : public User { /* menu() with student options */ };
class Admin   : public User { /* menu() with admin options  */ };
```
- `public User` = inheritance: Student/Admin automatically get `username`, `searchByTitle()`, `searchById()`, `viewSorted()`.
- **How `u->menu()` picks the right menu:** every object of a class with `virtual` functions carries a hidden pointer to a small table of that class's functions (the *vtable*). The call looks inside the real object's table at run time, so a `Student` runs `Student::menu`, an `Admin` runs `Admin::menu`, although the variable type is `User*`.

### 4.10 The recommender (`oop.cpp`)
```cpp
for (Book *b = getHead(); b != NULL && m < MAX_BOOKS; b = b->next) {   // every book
    int s = 0;  bool alreadyRead = false;
    for (int i = 0; i < n; i++) {                       // every book in the user's history
        if (history[i] == b->id) { alreadyRead = true; break; }
        Book *old = findById(history[i]);               // a book the user read earlier
        if (old == NULL) continue;                      // it was deleted later
        if (strcmp(old->genre,  b->genre)  == 0) s += 2;    // same genre  -> +2
        if (strcmp(old->author, b->author) == 0) s += 3;    // same author -> +3
    }
    if (alreadyRead || s == 0) continue;                // skip read books and no-match books
    cand[m] = b;  score[m] = s;  m++;                   // keep this candidate
}
```
- `cand[]` and `score[]` are **fixed arrays** (`MAX_BOOKS` long), so there is no `new`/`delete` to forget.
- `strcmp(a, b) == 0` means "the two texts are equal".
- After this loop a **bubble sort** puts the highest score first (swapping `cand[j]` and `score[j]` together), and the top 5 are printed.
- Inheritance and polymorphism are shown by `User` / `Student` / `Admin` (section 4.9); the Recommender is a separate, simple class.

### 4.11 Login (`loginUser`, `oop.cpp`)
```cpp
char *parts[3];                                        // parts[0]=name, parts[1]=password, parts[2]=role
while (fgets(line, sizeof(line), f) != NULL) {
    if (splitLine(line, parts, 3) != 3) continue;      // skip bad / blank line
    if (name == parts[0] && password == parts[1]) {    // both must match
        fclose(f);
        if (strcmp(parts[2], "admin") == 0) return new Admin(name);
        return new Student(name);
    }
}
```
The function returns a `User*`. `main` then calls `u->menu()` without ever asking "is this a Student or Admin?" - that decision is hidden in the object.

### 4.12 `main()` loop (`main.cpp`)
```cpp
loadBooks();                              // 1. data into memory
do {                                      // 2. repeat until Exit
    choice = readInt("Choice: ");
    if (choice == 1) {
        User *u = loginUser(name, pass);
        if (u == NULL) cout << "Wrong username or password.\n";
        else { u->menu(); delete u; }     // 3. role menu runs until Logout, then free the object

} while (choice != 0);
```

## 5. Full traces (state changes)

### 5.1 "priya searches `harry`"
1. `Student::menu` -> option 1 -> `User::searchByTitle`.
2. `readLine` gets `harry`.
3. `findByTitle("harry")` walks the BST: no title is exactly "harry" -> `NULL`.
4. `searchTitleContains("harry")` -> `walkContains` in-order; prints header once, then **202 Chamber of Secrets**, then **201 Sorcerer's Stone** (alphabetical: "Chamber" < "Sorcerer's").
5. No file is changed.

### 5.2 "rahul issues book 201"
| Step | Memory | `books.txt` | `issues.txt` |
|---|---|---|---|
| Before | Book 201: available 1, timesIssued 3 | `201|...|1|3` | (no rahul-201 line) |
| `findById(201)` | slot `201 % 101 = 100` -> pointer to node 201 | - | - |
| `issueBook` | available 0, timesIssued 4 | `201|...|0|4` | `rahul|201|ISSUED` added |
| Second issue attempt | `available == 0` -> returns `-1` | unchanged | unchanged |
| `returnBook` | available 1 | `201|...|1|4` | line becomes `rahul|201|RETURNED` |

### 5.3 "priya asks for recommendations"
1. `getUserHistory("priya")` reads `issues.txt` -> ids `[201, 203, 102]`.
2. For each book not in the history (e.g. 202): history book 201 has the same genre (+2) **and** the same author (+3); history book 203 has the same genre (+2) -> total **7** -> candidate.
3. For 204: genre +2 (from 201) +2 (from 203), author +3 (Tolkien, from 203) = **7**. For 105: Programming matches 102 -> **2**. For 205 (Fiction, no match) -> 0 -> dropped.
4. Bubble sort high -> low; ties keep file order -> `204, 202, 105, 101, 103` (matches the test output).
